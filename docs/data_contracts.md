# Data contracts and import

`src/services/repository.ts` validates a versioned monthly aggregate bundle with Zod. The default mode reads `public/data/status.json`; when `available` is false it displays an empty state. To load reviewed data, place a JSON file at `public/data/dataset.json`, conforming to the runtime schema, and set `available` to true. The bundle requires a real classification, provenance, nonnegative monthly records, matching record count and a review object with reviewer, date and evidence URL. Validation detects malformed structure; it **cannot verify source authenticity or scientific validity**. The operator must independently review the source, calculations and evidence before publishing the file. Review fields are assertions, not cryptographic proof.

The fixture in `data/fixtures/monthly.synthetic.json` is invented and selected only with the explicit preview control. A persistent global banner marks the preview, and the app does not fall back to it on real-data errors. Aggregates power only the seasonal chart. Raw CSV ingestion, spatial GeoJSON rendering, full manifest schema alignment and scientific pipelines remain future work; no UI component reads raw CSV files. The preliminary schemas under `schemas/` are not used by the runtime validator and must not be mistaken for its exact contract.

TypeScript contracts in `src/contracts.ts` cover planned observations, cells, stations, inventory, costs, optimization and validation. Future processing should retain raw inputs separately, normalize UTC timestamps and sensor confidence, preserve sensor provenance, and emit independently reviewed outputs with versioned metadata. Train on 2013–2020, validate on 2021–2022 and hold out 2023; do not tune on the test event.

Sprint 02 adds `pipeline/core.py` and `pipeline/publish.py`: the former writes a schema-validated versioned ingestion manifest and GeoJSON, while the latter verifies source file hashes and requires an explicit reviewer and evidence before publishing sanitized real outputs. Python output contracts remain distinct from the existing monthly frontend contract. The separate publish step adapts reviewed Parquet into that frontend contract. The reviewer and URL fields are claims, not an authenticity guarantee.
