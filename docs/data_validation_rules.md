# Validation rules

CSV/ZIP input is parsed as UTF-8 with documented column signatures. Files lacking required columns, ambiguous sensor schemas, malformed CSV, malformed archives or unsafe ZIP paths produce file errors. CSV members are read in memory rather than extracted. Limits are applied to ZIP entry count and uncompressed size. Data rows with invalid coordinates, times, sensor/satellite, sensor-specific confidence, negative FRP, nonpositive scan/track or brightness, or invalid day/night are rejected with reason and raw JSON. Missing optional fields are retained as null with quality flags. No empirical confidence threshold is applied. Bounds first apply an inclusive rectangle, then the default verified Maui coastline polygon with the edge-inclusive covers predicate. A configured but invalid boundary fails; bbox-only fallback is explicitly labeled provisional. Points outside the selected geographic filter and period are counted and retained in an excluded-record output. Processing version suffixes are identified according to NASA documentation; absent or unfamiliar versions are unknown. Mixed types and versions are explicitly flagged.

Counts reconcile as received = accepted + rejected + geographic exclusions + temporal exclusions + exact duplicates. File-level failures are reported separately because their row counts cannot be trusted. The exact duplicate key uses a stable hash of the full source row and sensor; it does not identify the same incident across sensors. Different values and timestamps remain separate.
The sample generated report records years with no accepted detections only as no-detection years; coverage data is unavailable, so this is not a fire-free or clear-sky claim. The data manager exposes basic counts, file hashes and processing warnings; full report views and nonstandard CSV formats require further work.
